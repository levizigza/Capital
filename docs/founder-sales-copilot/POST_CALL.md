# Post-call capture & classification

Capture during/after. Separate **what they said** from founder interpretation.

## Capture fields

| Field | |
|-------|--|
| **problem** | In their words |
| **severity** | How bad when it happens |
| **urgency** | Why now / why not |
| **desired_outcome** | Future state they named |
| **existing_solution** | What they use now |
| **decision_maker** | Who chooses / who pays |
| **budget_signals** | What they’ve paid; process; timing |
| **objections** | Verbatim concerns |
| **next_step** | Dated, owned |

## Classification (pick one primary)

| Class | Meaning |
|-------|---------|
| **NOT_ICP** | Wrong problem or wrong buyer for Capital as it exists |
| **RESEARCH_USER** | Valuable for learning; not a near-term sale |
| **QUALIFIED** | ICP-fit + pain + decision access; not ready to pay yet |
| **PILOT_CANDIDATE** | Will run a bounded trial with success criteria |
| **READY_TO_BUY** | Clear buyer, fit, urgency, and intent to pay now |
| **FOLLOW_UP** | Timing/process block; scheduled next touch |
| **LOST** | Explicit no / ghost after agreed cadence |

## If READY_TO_BUY

1. Confirm inclusions match **shipped** product (no invented features).  
2. Use simplest approved payment mechanism (`PAYMENT.md`).  
3. Do **not** delay for unfinished automated billing.  
4. File Stripe Payment Link request if that mechanism is approved and available.  
5. Log class + payment path in the call note.

## If RESEARCH_USER

Hand evidence to Customer Interview / Usability agents. Do not force a close.
