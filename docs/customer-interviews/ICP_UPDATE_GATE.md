# ICP update gate

Canonical segment assumptions live in design docs (e.g. `docs/game-pillars.md` Target customers).  
Discovery treats them as **hypotheses** (`docs/customer-discovery/HYPOTHESES.md` when present).

## Do not update ICP when

- You finished **1** interview (any segment)  
- Someone said they “would use” or “love” Capital in PRODUCT REACTION  
- Warm-network friends agree with the founder story  
- A single paid alternative was mentioned  

## May propose an ICP amendment only when

| Gate | Requirement |
|------|-------------|
| Recurrence | Same behavioral pattern in **≥3** evidence records **or** ≥50% of a completed interview cohort (n≥4) |
| Segment clarity | Same `segment` id (don’t mix S1 quotes into S7 ICP) |
| Behavior not compliments | Pattern is about pain/frequency/alternatives/spend/decision-maker — not product flattery |
| Review | Written proposal in `evidence/ICP_PROPOSALS.md` with evidence ids — **human** merges to pillars |

## Process

1. After each interview → evidence DB only.  
2. Weekly: scan index for recurring pain/alternative themes.  
3. If gates met → draft proposal (still a hypothesis until merged).  
4. Never silently edit game-pillars ICP from this agent.
