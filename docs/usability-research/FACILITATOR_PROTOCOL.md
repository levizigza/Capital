# Facilitator protocol

## Before the session

1. Confirm cohort + screener round (`docs/user-research-recruitment/`).  
2. Fresh profile / clean browser profile unless the test’s **STARTING STATE** says otherwise.  
3. Desktop **and** note device (phone if testing mobile). Record `prefers-reduced-motion` if OS has it on.  
4. Consent: recording optional; no child’s legal name in notes.  
5. Open observation log (one per participant, de-identified id `P-A1-01`).

## Opening script (adapt; keep short)

> I’m going to give you goals — not step-by-step instructions.  
> Please say out loud what you’re looking for and what you think will happen.  
> There are no wrong answers. If something is confusing, that’s useful.  
> I can’t help you finish the task, but I can repeat the goal.

## Allowed facilitator moves

| OK | Not OK |
|----|--------|
| Repeat the task goal in the same words | “Click the carpet” / “Talk to Piggy” |
| “What are you trying to do right now?” | “The game wants you to…” |
| “What did you expect to happen?” | Defending: “Most people miss that because…” |
| “Show me what you’d do next” | Taking the mouse / completing for them |
| Note silence ≥3s as hesitation | Filling silence with hints |
| End task on abandon after clear stuck (≥2 min or they say stop) | Teaching the intended path |

## Bad vs good task phrasing

**BAD:** “Click Investments, select a stock, and buy it.”  
**GOOD:** “You have money you want to grow over time. Show me what you would do.”

**BAD (Capital):** “Press E near Piggy, then board the Money Carpet to Coincraft Cove.”  
**GOOD:** “You’ve just arrived. Figure out how to start your first money adventure away from this place.”

## Capture checklist (every task)

- Hesitation (where, how long)  
- Misinterpretation of UI/copy  
- Questions asked (to facilitator or self)  
- Mistakes / wrong targets  
- Expectation mismatches (“I thought that would…”)  
- Abandonment  
- Delight (smile, “oh!”, lean-in)  
- Uninstructed discovery  
- Time to success (or time to abandon)  
- Cause ↔ effect understanding (can they retell what their choice did?)

## After each task

Mark **Success / Fail / Partial** against the written SUCCESS and FAILURE conditions **before** discussing anything.  
Do not debrief design intent until **all** tasks for the session are done (optional post-session interview is separate from observational scoring).

## Post-session (optional, after scoring)

Only then: light interview from discovery plan (WTP, rails vs fiction). Keep observational classifications frozen — do not rewrite Success/Fail based on later rationalizations.
